## (a) Goal and rules

**Goal.** One *valid* oracle demo for each of the 21 subtasks (the "first-demo pass"), produced by the v2 pipeline
(`ground_isg` → `sample_isg` → `run_isg --mode oracle`) on the representative variants only (`ispatialgym/assets/icl/roles/representatives.csv`,
customs `ispatialgym/assets/task_specs/isg_customs.json`). Coverage sampling (many templates per subtask) is **paused** by the owner
(`runlogs/pilot_20260915/paused_for_resume.md`, `wave_a/jobs_rest.json`, the `rest_009` chunk, the fallback wave — do not resume).

**Validity rule (owner 06:50 + D-005 freeze, 19:36).** A demo is valid when it succeeded *and* its code commit contains every
**targeted** fix-log entry affecting the subtask — an entry naming fewer than 6 subtasks (`runlogs/pilot_20260915/fix_log.jsonl`;
`kind: facts` / `note` entries never count). Blanket entries (≥ 6 subtasks or `*`) do not re-open a valid row; the board shows
`valid demo (pre-<sha>)` and **one final validity sweep** (re-run every valid row on HEAD) closes the pass. A valid row is re-run only
by a targeted fix or an owner `RUN:`. Implemented in `scripts/isg/first_demo.py` (`demo_valid`, `fixes_for(targeted_only)`).

**Loop mechanics.** `scripts/isg/first_demo.py run --variant A [--scene S] [--max-attempts 8] [--timeout 7200] [--note ..]` samples one
template × one instance on a free pool pod (`scripts/runpod/remote_run.py`: working tree synced, one lock per pod) and runs the oracle
demo, appending a row to `runlogs/pilot_20260915/first_demo/ledger.jsonl` and regenerating the board. `demo-only --tro <tro>` re-runs
an existing instance. `fix --commit <sha> --subtasks .. --what .. --owner .. [--kind fix|facts|note|icl]` logs a fix.
`scripts/isg/pod_scheduler.py loop` (stopped at shutdown) re-runs a subtask automatically when a fix-log entry affecting it lands and
its last run predates that entry; `hold` / `release` / `add` / `cancel` (cancel SIGTERMs the remote_run child first — its handler kills
the pod-side tree). Owner decisions are recorded in `runlogs/pilot_20260915/pending_decisions.json` (`scripts/isg/slack_bridge.py`).

**Budget.** Cap $1000 (`rp.py DEFAULT_CAP_USD`, a `create` guard + log line only; the watchdog never terminates for budget).
Spent at shutdown (03:38 PDT): **balance $30.95, spent_total $728.18 of the $1000 cap, 31 recharges** (`runlogs/runpod/billing.log`). The owner recharges the
RunPod balance in small amounts; `python scripts/runpod/rp.py balance` is the signal. Cost figures: A40 $0.49/h, L40S $1.09/h.
**All pods are terminated as of this hand-off** (owner 02:15); a new fleet has to be created (see `docs/runpod_operations.md`).

## (e) Known pitfalls

- `pgrep -f` / `pkill -f` self-match: a pattern is part of its own command line — use the bracket trick (`pod_scheduler.py loo[p]`) and **never
  put the kill and the relaunch in the same shell command** (the relaunch text matches and the shell kills itself — happened three times today).
- `/root/samp/current.txt` is written at a job's start and never cleared between jobs; `done.txt` keeps earlier attempts — a band pod is running
  iff `/root/samp/running/*.job` exists (`fleet_remaining.py`, `pod_scheduler.py` use that).
- `remote_run.py`: one flock per pod (`runlogs/runpod/smoke/locks/<pod>.lock`) held for the whole run including backgrounded children; a killed
  remote_run only kills the pod-side tree if it is alive to run its SIGTERM handler (`pod_scheduler.py cancel` does it right; a plain `kill` of the
  parent `first_demo.py` leaves an orphan on the pod — seen 17:29).
- The pods sync the **working tree** (uncommitted edits included): a half-edited file at sync time breaks the run on the pod (two wasted runs today).
  Commit small; never leave a file half-edited between commits.
- Validity churn: core-wide sampler changes re-opened valid rows all afternoon until D-005 (targeted = < 6 subtasks; batch core-wide changes).
- Transcript timestamps, not message content, tell whether an agent is alive (the 00:00 cut-off).
- `dde4f11`'s 0.05 rad joint-limit margin is right for grasps but blocks the wall pushes (joint 2 at its limit is the only way to push a wall
  target) — an exemption per contact kind is owed.
- The B4 inventory's `front_free_m` for cabinets came from the no-object traversability map (bamfsz_0: 3.0 m claimed, 0.0 m real).
- OmniGibson's `Under` on concave partners is fragile (→ the predicate wrapper); the AG attaches on two-finger contact, so closure asymmetry
  moves the object (→ ramp, pre-shape, symmetric closure).
